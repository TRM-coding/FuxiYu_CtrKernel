## 设计

使用 `users` 与 `registration_codes.created_at` 查询已注册邮箱和近期请求。写入验证码前，同一进程内串行检查与创建；60 秒内重复请求返回 429。已注册邮箱返回 409，不写验证码、不发邮件。验证码创建后发信失败仍计入冷却，避免重试风暴。数据库表与字段不变。

进程锁不提供跨进程或跨机器原子保证；也不限制不同邮箱或 IP 的请求。部署层的分布式限流是独立能力，不能把此补丁表述为完整防滥用方案。

成功响应与 `rate_limited` 响应均在响应体顶层提供整数 `retry_after_seconds`，由本邮箱实际参与节流的验证码创建时间和同一个 60 秒期限计算；不足一秒向上取整，最小值为 0。成功发信耗时计入冷却，不能固定返回 60。其他失败不携带该字段；请求超时或响应丢失时客户端也不能假定有剩余时间。发信失败后已有记录仍参与现有冷却，之后再次请求若命中冷却，则按 `rate_limited` 返回实际剩余时间。
