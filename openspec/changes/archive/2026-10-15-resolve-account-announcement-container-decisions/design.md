# Design

## Context

现有规格按数据表组织，服务层组合认证、公告、容器恢复等行为。恢复会调用 Node，数据库回滚不能撤销外部创建；模板引用还可能留在既有库中。动机见 proposal.md，行为边界见各 delta。

## Goals / Non-Goals

**Goals:** 在现有分层内统一规则；保证无权操作他人草稿时无数据副作用；长期配额拒绝可重试；既有库模板引用不阻塞删除。

**Non-Goals:** 不替换认证策略、公告投递引擎或容器创建协议；不扩展为全库迁移体系改造；不增加自定义组最后管理者保护。

## Decisions

1. 认证依赖区分身份与权限，令 401 和 403 表达不同含义。用户删除在最终事务内处理认证记录；业务容器归属的拒绝沿用 wild_container，不用笼统的数据库异常掩盖原因。
2. 模板作为填充值来源，草稿和公告继续持有正文快照。兼容历史 template_id 输入但不建立新的有效引用；删除模板时同事务解除既有引用，保留正文。相比级联删除草稿，这能保留每个人的编辑内容与发送历史。
3. 草稿在仓储或服务入口统一校验 created_by；批量发送先验证所有待用草稿的归属，不把列表过滤当作完整访问控制。
4. 自定义组实体整组替换可接受空集合；更新后权限立即由新集合派生，内置 operator 的锁定规则仍有效。
5. 抽出有效冻结天数的纯计算并供查询和调度共用，保留调度的维护、在线状态、宽限门控。
6. 长期恢复沿用普通设置的配额主体与计数，将容量错误前移到 Node 创建之前，成功后才消费恢复产物；不把失败留到容器已复活后再拒绝或静默丢标记。

## Risks / Trade-offs

- 历史模板外键仍在旧库中 → 通过现有升级载体或删除事务解除引用验证旧库路径，不依赖 create_all 修改既有表。
- Node 外部创建不能随本地事务自动撤销 → 容量检查和容量保护放在恢复创建之前，失败用例同时断言未调用 Node、快照及挂载记录保留。
- 私有草稿令过去可跨操作员使用的 id 被拒绝 → 返回现有可理解的拒绝响应，保留原草稿，不提供隐含管理豁免。
- 普通设置和恢复均先计数再写入，未形成原子配额预留 → 本次增加同口径预检，保留可重试失败语义；并发配额策略单列 Q67，不能把预检宣称为原子保证。
- 公告、模板和草稿的作者外键仍可能阻止删除用户 → 本次只清理 Token 并纠正异常归因，内容保留与作者归档策略单列 Q68。

## Migration Plan

应用按现有启动和数据库升级路径处理兼容数据；自定义模板删除事务同样处理遗留引用。发布后新保存的草稿与公告不再产生有效模板关联。回滚前评估新私有语义和历史引用解除的影响；正文快照不随引用解除丢失。
